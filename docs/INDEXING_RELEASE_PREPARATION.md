Baseline: latest GitHub main `eb2fb6a`. No production deployment or indexing activation is authorized by this preparation PR. `site.productionIndexing` and the existing deployment request remain false; `.github/pages-deployment-request.json` is deliberately unchanged, so this PR does not request a live deployment.

The proposed shared indexing policy coordinates metadata, robots and sitemap. 404, the withheld patient-experiences notice and four existing single-article category routes remain noindex and are excluded from the sitemap. This changes the proposed sitemap from 58 entries to 53 while retaining all 58 existing public routes, 28 services, 12 articles, seven category pages and five educational videos. Public URL inventory is not the same as indexable sitemap inventory. Preview always disallows crawling and stays noindex, even when the production flag is true.

A future indexing-enabled release must deliberately change the site boolean and deployment-request boolean together. It additionally requires explicit `indexingApproved: true` and a non-sensitive `indexingApprovalRef` in the request; actual privacy-policy and clinical-readiness approvals with approver/date/reference in `.github/publication-readiness.json`; and that record's `publicationInventorySha256` must match `node scripts/verify-indexing-release.mjs` output for the exact prepared content/contact/policy inventory. Changing reviewed content invalidates the digest. These are evidence checks, not automatic verification of the documents or legal compliance. Never insert sensitive evidence in public GitHub.

The standard test command and production deployment guard reject inconsistent requests and missing readiness evidence. The deployment still requires a reviewed request change or an APPROVED main-only manual dispatch, and both-mode Actions validation before artifact construction/deployment. The guard change itself does not switch indexing on. The readiness bundle remains non-deploying; its manifest describes the actual configured indexing mode and checksums.

Current production remains blocked and unchanged.
